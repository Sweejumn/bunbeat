# RunBPM 服务器部署指南

把应用挂到自己的服务器上，让别人通过网址使用。

## 0. 服务器要求

- 系统：**Ubuntu 22.04 / 24.04**（Debian 也行；CentOS 命令略有差异，见文末）
- 内存：建议 **2GB 以上**。1GB 也能跑（脚本已默认分析并发=1），但处理音频会慢一些
- 不需要提前装 ffmpeg / node（ffmpeg 由 pip 包自带，前端已在 Windows 上构建好）

## 1. 在 Windows 本机打包（PowerShell）

在 `C:\Users\123\Desktop` 下执行（排除本机数据、node_modules、git 等，**包含**构建好的 `frontend/dist`）：

```powershell
cd C:\Users\123\Desktop
tar -czf runbpm-deploy.tar.gz --exclude='muzrun/backend/data' --exclude='muzrun/frontend/node_modules' --exclude='muzrun/sandbox' --exclude='muzrun/.git' muzrun
```

## 2. 上传到服务器

```powershell
scp C:\Users\123\Desktop\runbpm-deploy.tar.gz root@你的服务器IP:/tmp/
```

## 3. 一键部署

```bash
# SSH 登录服务器后执行：
mkdir -p /opt/runbpm
tar -xzf /tmp/runbpm-deploy.tar.gz -C /opt/runbpm --strip-components=1
cd /opt/runbpm
sudo bash deploy/setup.sh
```

脚本会：装依赖 → 建 Python 虚拟环境 → 装 pip 依赖 → 创建 `runbpm` 用户 → 安装并启动 systemd 服务 → 放行 8000 端口。

## 4. 放行端口（最容易漏的一步）

- 脚本已处理服务器自带防火墙（ufw）
- **云厂商控制台的安全组还要手动放行**：阿里云 / 腾讯云 → 云服务器 → 安全组 → 入方向规则 → 添加 **TCP 8000**（来源 0.0.0.0/0）

## 5. 访问

- 服务器上验证：`curl http://127.0.0.1:8000/api/health` 应返回 `{"status":"ok"}` 之类
- 手机 / 其他人浏览器打开：`http://服务器IP:8000`

> 注意：应用**没有登录鉴权**，知道网址的人都能上传歌曲、占用 CPU 分析。只想给熟人用，建议做第 7 步加密码。

## 6.（可选）域名 + HTTPS

```bash
sudo apt install -y nginx certbot python3-certbot-nginx
sudo cp /opt/runbpm/deploy/nginx.conf.example /etc/nginx/conf.d/runbpm.conf
sudo nano /etc/nginx/conf.d/runbpm.conf     # 改 server_name
sudo nginx -t && sudo systemctl reload nginx
# 后端只监听本机，避免 8000 裸奔：
sudo sed -i 's/python run.py 0.0.0.0/python run.py 127.0.0.1/' /etc/systemd/system/runbpm.service
sudo systemctl daemon-reload && sudo systemctl restart runbpm
sudo ufw allow 80,443/tcp
sudo certbot --nginx -d 你的域名.com
```

之后访问 `https://你的域名.com`。

## 7.（可选）加访问密码

```bash
sudo apt install -y apache2-utils
sudo htpasswd -c /etc/nginx/runbpm.htpasswd 用户名
```

然后编辑 `/etc/nginx/conf.d/runbpm.conf`，把模板里 `auth_basic` 两行注释去掉，`nginx -t && systemctl reload nginx`。

## 8. 日常运维

```bash
sudo systemctl status runbpm          # 状态
sudo journalctl -u runbpm -f          # 实时日志
sudo systemctl restart runbpm         # 重启
```

## 9. 升级代码

1. Windows 上 `npm.cmd run build`（更新前端）
2. 重新执行第 1、2 步打包上传
3. 服务器上解压覆盖（**tarball 不含 data，所以不会碰服务器的歌曲数据**）：

```bash
tar -xzf /tmp/runbpm-deploy.tar.gz -C /opt/runbpm --strip-components=1
sudo systemctl restart runbpm
```

## 10. 备份数据

所有数据（数据库 + 上传原曲 + 处理结果）都在 `/opt/runbpm/data`：

```bash
sudo tar -czf ~/runbpm-data-backup.tar.gz /opt/runbpm/data
```

## 常见问题

| 现象 | 原因 / 解决 |
| --- | --- |
| 手机打不开，电脑 curl 通 | 云厂商安全组没放行 8000，去控制台加规则 |
| 页面是旧版本 | 浏览器缓存，强制刷新（手机清缓存或换无痕窗口） |
| 处理歌曲很慢 | 服务器内存小，脚本已默认分析并发=1；升级内存或调 `RUNBPM_MAX_CONCURRENT_ANALYZE` |
| pip 安装报错（Python 3.12） | 换 Python 3.10/3.11 的镜像或 `apt install python3.11 python3.11-venv` 后手动重建 venv |

## CentOS / 宝塔系统

大体相同，差异点：包管理用 `yum install -y python3 python3-pip ffmpeg`；服务文件放到
`/usr/lib/systemd/system/runbpm.service`（或宝塔面板的 systemd 管理里创建）；防火墙用
`firewall-cmd --permanent --add-port=8000/tcp && firewall-cmd --reload`；安全组放行照旧。
