# Bunbeat · 基于 BPM 的本地跑步音乐播放器（安卓离线版）

**让音乐跟随你的跑步节奏。**

Bunbeat 是一款安卓离线音乐播放器：直接读取你手机本地的音乐文件夹，自动识别每首歌的 BPM，
按运动模式推荐歌曲，将每首变速统一到目标 BPM（**保持音高不变**），并用节拍器逐拍对齐真实拍点连续播放。
全部处理都在设备端完成——**无需联网、无需上传、不依赖任何第三方服务器**。

> 本仓库 = 安卓 App（`android_app/`，当前主力）+ 早期 Web 版（`backend/` + `frontend/`，见文末）。

## 功能特性

### 本地音乐导入与 BPM 分析

- 📁 **本地文件夹直读**：内置目录选择器（Android SAF）选一个文件夹后，通过 MediaStore
  （`on_audio_query`）读取其中的 MP3 / WAV / M4A / FLAC / OGG 等音频。
  分区存储下用 MediaStore 查询 + 真实绝对路径直接读取播放。
- 🔍 **设备端 BPM 分析**：纯 Dart 实现的 FFT + 自相关分析（移植自 Web 版的 librosa 逻辑），
  解析 BPM 与拍点，含八度 / 脉冲修正；分析在**后台 isolate** 执行，不阻塞界面。
- ✏️ **手动改 BPM / 重新检测**：检测不准时直接手动输入，或长按重新检测、BPM ×2。
- 📑 **归档**：不想看到的歌一键归档隐藏（从曲库与推荐移除），需要时在归档页放回。
- 🔎 **排序与搜索**：按默认 / 标题 / BPM / 时长排序，按歌名 / 歌手筛选。

### 运动模式与推荐

- 🏃 **一根滑块覆盖 4 个区间**：走路 100–120 · 慢跑 120–145 · 跑步 145–165 · 快跑 165–185，
  拖到哪就是哪档；支持任意目标 BPM（40–300）手动输入。
- ⭐ **推荐列表**：按 `|原BPM − 目标BPM|` 距离排序；每行显示方向箭头、差距百分比、
  颜色分级（<3% 等号、3–8% 轻微变速↑/↓、8–12% 红色变速多、>12% 红 ✕ 不适合变速）。
- ✅ **多选操作**：单选或长按多选后，可一键**加入播放列表、归档、重新检测、BPM ×2**，
  全部同时作用于所选歌曲。

### 播放、变速与节拍器

- ▶️ **连续播放**：播放 / 暂停 / 上一首 / 下一首、进度拖动、导航栏循环 / 单曲 / 随机。
- ⏩ **保持音高的变速**：基于 ExoPlayer 的 `speed`（时间拉伸），把 0.5–2.0 倍内的歌曲统一到目标 BPM，
  **音高不变**、不会「花栗鼠」。
- 🥁 **节拍器**：与当前歌曲真实拍点（或等距网格）逐拍对齐的前瞻调度器，多套音效、可调音量与打拍校准。
- 📏 **拍点标尺**：用主题色画出每个拍点，播放时实时滚过中心线；偏差可整体微调，所见即所听。
- 📥 **播放列表（队列）**：右下角打开可跳歌、长按拖动排序、删除单首、清空。

### 可靠性 / 易用

- 📱 **移动优先**：底部导航（曲库 / 推荐 / 播放）与长按菜单，拇指友好。
- 🎨 **外观可定制**：跟随系统 / 浅色 / 深色主题 + 主题色，实时生效。
- 🔄 **内置更新**：「设置 → 检查更新」从 GitHub Release 拉取最新 APK，直接自装（设备离线时手动安装历史版本）。
- 🔒 **全离线本地处理**：不抓取音乐平台、不上传任何数据，仅处理用户本地文件。

## 技术栈

| 层 | 技术 |
|---|---|
| 框架 | Flutter（Dart），Flutter 3.47 / Dart 3.13 |
| 状态管理 | Provider |
| 播放 / 变速 | just_audio（ExoPlayer，变速默认保持音高） |
| 文件夹选择 | file_picker（Android SAF 目录选择器） |
| 扫描音频 | on_audio_query（MediaStore 查询，兼容分区存储） |
| 音频解码（用于 BPM） | ffmpeg_kit_flutter_audio → PCM 后本地分析 |
| 系统要求 | Android（minSdk 24 起，真机 Vivo 验证） |

## 安装与构建

```bash
cd android_app
flutter pub get
flutter build apk --release
```

产物在 `build/app/outputs/flutter-apk/app-release.apk`。用数据线连接手机（开启 USB 调试）后
`flutter install`，或直接把 APK 复制到手机安装。

> 已装旧版本时，新 APK 的版本号（内部 build 号）必须高于当前版本，否则 Vivo 等系统会拒绝安装。
> 手机不在手边时，也可在「设置 → 检查更新」里自动从 GitHub Release 安装最新版。

### 发布流程（维护者）

每次改动遵循固定流程：`flutter analyze` + `flutter test`（保持 0 error / 全绿）
→ 在 `pubspec.yaml` 递增构建号（`0.1.0+N`）→ `flutter build apk --release`
→ 提交推送 → 在 GitHub 创建发行版（`v0.1.0+N`，非预发布）并上传 APK
（文件名 `Bunbeat-v0.1.0.N.apk`）。App 的「检查更新」读取 `releases/latest` 作为唯一更新来源。

## 使用方法

1. 打开 App，点顶部「添加音乐」（选定文件夹后显示为「音源」，功能一致），通过系统目录选择器挑选音乐文件夹。
2. App 递归扫描并逐个分析每首歌的 BPM（顶部显示进度「分析中…」）。
3. 分析完每首歌显示 BPM 与可信度；不准的可长按「重新检测」或在曲库点 ✏️ 手动修改。
4. 「推荐」页选运动模式、微调目标 BPM，勾选想听的歌，点「变速并播放」；或回曲库长按多选加入播放列表。
5. 「播放」页开始连续播放；可打开节拍器并调音量，也可切循环 / 随机模式。

## 常见问题

- **打了音乐文件夹却显示 0 首**：Android 10+ 分区存储需授予「音乐和音频」权限
  （`READ_MEDIA_AUDIO`，Android 13+）；授权后重新选一次文件夹。
- **BPM 分析不准 / 报错**：FFT 自相关简化实现，对很自由 / 很短的音频可能不准，手动改 BPM 即可；
  不支持的格式会用 ffmpeg 解码一小段后明确报错。
- **变速要求过高会失真**：`just_audio` 的 `speed` 在 0.5–2.0 外效果明显失真，代码已限速在 0.5–2.0，
  请选更接近原 BPM 的目标。
- **节拍器没声音**：在「播放」页打开开关并确认拍子音量；首次打开会先生成嗒声文件。
- **提示已加入播放列表却切页后消失**：SnackBar 提示只停留在当前界面，切换底部页面时会立即收起，属正常设计。

## 与 Web 版的关系

早期仓库是 **Web 版（RUN BPM）**：上传音乐 → 后端 librosa 分析 → FFmpeg 变速 → 浏览器播放，
需要运行 FastAPI + SQLite 后端。如今能力已全部移植到**安卓端**并持续迭代，Bunbeat 成为产品主力。

两版的运动模式、推荐规则（距离 + 星级/颜色）、节拍对齐理念一致，只是把 Web 端的「上传 → 服务器处理」
换成了安卓端的「本地读文件夹 → 设备端处理」，**彻底离线、无需服务器**。

> 仍在仓库内保留的 Web 版源码（`backend/`、`frontend/`）为历史版本，仅供查阅，不再接受新需求。
